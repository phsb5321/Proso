# Data Model: UnoCSS Integration for Extension Styling

**Feature**: 075-unocss-integration
**Date**: 2026-03-05

---

## Overview

This feature is a build-time tooling integration — it does not introduce new runtime entities, database tables, or state machines. The "data model" consists of configuration entities and their relationships.

---

## Entity: UnoCSS Configuration (`uno.config.ts`)

The central configuration file that defines how UnoCSS generates utility classes.

### Fields

| Field | Type | Description | Source |
|---|---|---|---|
| `presets` | `Preset[]` | Enabled utility presets | Static config |
| `presets[].presetWind3` | `PresetWind3Options` | Tailwind v3-compatible utility classes | `unocss` |
| `presets[].presetIcons` | `PresetIconsOptions` | Pure CSS icon system | `unocss` |
| `presets[].presetRemToPx` | `PresetRemToPxOptions` | rem→px conversion (16px base) | `@unocss/preset-rem-to-px` |
| `transformers` | `Transformer[]` | CSS directive transformers | Static config |
| `transformers[].directives` | `TransformerDirectivesOptions` | `@apply`, `theme()`, `@screen` support | `unocss` |
| `theme` | `ThemeConfig` | Design token → utility class mapping | `tokens.css` via `var()` |
| `theme.colors` | `Record<string, string \| Record>` | Color token references | `tokens.css` |
| `theme.spacing` | `Record<string, string>` | Spacing scale references | `tokens.css` |
| `theme.fontSize` | `Record<string, string>` | Typography size references | `tokens.css` |
| `theme.fontWeight` | `Record<string, string>` | Font weight references | `tokens.css` |
| `theme.lineHeight` | `Record<string, string>` | Line height references | `tokens.css` |
| `theme.borderRadius` | `Record<string, string>` | Border radius references | `tokens.css` |
| `theme.boxShadow` | `Record<string, string>` | Shadow references | `tokens.css` |
| `theme.fontFamily` | `Record<string, string>` | Font family references | `tokens.css` |
| `theme.zIndex` | `Record<string, string>` | Z-index layer references | `tokens.css` |
| `rules` | `Rule[]` | Custom utility rules for non-standard tokens | Static config |
| `shortcuts` | `Record<string, string>` | Named utility compositions | Static config |
| `content` | `ContentConfig` | File scanning configuration | Static config |
| `content.pipeline.include` | `(string \| RegExp)[]` | Files to scan for utility class usage | Static config |

### Validation Rules

- All `theme.colors.*` values MUST be `var(--color-*)` references matching `tokens.css`
- All `theme.spacing.*` values MUST be `var(--spacing-*)` references matching `tokens.css`
- `presetWind3` MUST be used (not `presetWind4`) to avoid CSS variable conflicts
- `presetRemToPx` MUST be included to ensure pixel-based output
- `content.pipeline.include` MUST include `'src/**/*.ts'` (not scanned by default)

## Entity: WXT Module Configuration (`wxt.config.ts`)

The WXT build configuration that registers the UnoCSS module.

### Fields

| Field | Type | Description |
|---|---|---|
| `modules` | `string[]` | Must include `'@wxt-dev/unocss'` |
| `unocss.excludeEntrypoints` | `string[]` | Entrypoints excluded from CSS processing |

### Validation Rules

- `modules` MUST contain `'@wxt-dev/unocss'`
- `unocss.excludeEntrypoints` MUST contain `['background', 'content']`
- Existing `vite()` function MUST NOT be modified (UnoCSS plugin is injected by the module)

---

## Entity: Entrypoint CSS Import

Each UI entrypoint must import the virtual UnoCSS stylesheet.

### Instances

| Entrypoint | File | Import | Layer Order |
|---|---|---|---|
| Popup | `src/entrypoints/popup/main.ts` | `import 'virtual:uno.css'` | tokens → uno → components → style |
| Options | `src/entrypoints/options/main.ts` | `import 'virtual:uno.css'` | tokens → uno → components → options |
| Content | `src/entrypoints/content.ts` | None (excluded) | N/A |
| Background | `src/entrypoints/background.ts` | None (excluded) | N/A |

### Validation Rules

- Popup and options entrypoints MUST import `'virtual:uno.css'`
- Content script MUST NOT import `'virtual:uno.css'`
- Background script MUST NOT import `'virtual:uno.css'`
- Import order determines CSS specificity; `virtual:uno.css` MUST come after tokens and before components

---

## Entity: Generated CSS Bundle (build output)

Per-entrypoint CSS files generated by UnoCSS at build time.

### Instances

| Entrypoint | Contains | Tree-Shaken |
|---|---|---|
| Popup CSS | Utility classes used in popup HTML + popup main.ts | Yes — only popup utilities |
| Options CSS | Utility classes used in settings HTML + options main.ts | Yes — only options utilities |
| Content CSS | No UnoCSS output | Excluded |
| Background | No CSS at all | Excluded |

### Validation Rules

- Each bundle MUST contain only utilities used in that entrypoint's source files
- Total size increase per entrypoint MUST be ≤ 5 KB
- No UnoCSS-generated CSS MUST appear in the content script bundle
- No CSS MUST appear in the background bundle

---

## Relationships

```
tokens.css (source of truth)
    │
    ▼
uno.config.ts (maps tokens to theme via var() references)
    │
    ├──→ wxt.config.ts (registers @wxt-dev/unocss module)
    │        │
    │        ├──→ popup Vite build → popup CSS bundle
    │        └──→ options Vite build → options CSS bundle
    │
    ├──→ popup/main.ts (import 'virtual:uno.css')
    ├──→ options/main.ts (import 'virtual:uno.css')
    │
    └──✕ content.ts (excluded)
    └──✕ background.ts (excluded)
```

## State Transitions

Not applicable — this feature has no runtime state. All processing occurs at build time.
