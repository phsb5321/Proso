# Implementation Plan: Complete Architecture Migration

**Branch**: `061-complete-architecture-migration` | **Date**: 2026-02-08 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/061-complete-architecture-migration/spec.md`

## Summary

VoxPage's hexagonal architecture migration (034-057) left the codebase architecturally sound but functionally broken end-to-end. Research identified 4 critical wiring failures: (1) Browser TTS adapter returns empty audio blobs instead of using `speechSynthesis` directly, (2) the highlight-sync adapter sends dot-notation message types that don't match the content script's SCREAMING_SNAKE_CASE expectations, (3) the popup sends legacy camelCase message names that no handler recognizes, and (4) language detection results are never passed to audio generation. Additionally, ~800 LOC of dead code exists from removed features (summarization AI, unused export wiring). This plan fixes all wiring, deletes dead code, and verifies end-to-end functionality.

## Implementation Phases

### Phase 1: Core Playback Chain (P1) — FR-001 through FR-006

**Goal**: User clicks Play → audio is audible → controls work.

1. **Fix Browser TTS adapter** (`browser-tts-audio.adapter.ts`)
   - Add `playbackMode: 'direct'` to adapter
   - Keep `speechSynthesis.speak()` as the audio output
   - Return `playedDirectly: true` in response so PlaybackService knows not to use HTMLAudioElement
   - Track utterance events (onend, onpause, onresume) for progress reporting

2. **Update PlaybackService** (`playback-service.ts`)
   - Check `response.playedDirectly` after `generateAudio()`
   - If true: track progress via estimated duration, skip `HTMLAudioElement`
   - If false: play blob via `HTMLAudioElement` as before (ElevenLabs path)
   - Support pause/resume/stop for both paths

3. **Update IAudioGenerator port** (`audio-generator.port.ts`)
   - Add optional `playbackMode: 'blob' | 'direct'` property
   - Add optional `playedDirectly: boolean` to `AudioResponse`

4. **Fix popup message names** (`popup/main.ts`)
   - Replace all 10 legacy camelCase names with dot-notation
   - Verify dispatch reaches hexagonal handlers

### Phase 2: Visual Feedback (P1) — FR-007 through FR-010

**Goal**: Footer appears, paragraphs highlight, state syncs.

5. **Fix highlight-sync adapter** (`highlight-sync.adapter.ts`)
   - Change `type: 'footer.show'` → `type: 'FOOTER_SHOW'`
   - Change `type: 'footer.hide'` → `type: 'FOOTER_HIDE'`
   - Change `type: 'footer.updateState'` → `type: 'FOOTER_STATE_UPDATE'`
   - Fix highlight message types similarly

6. **Verify content script routing** (`content.ts`)
   - Confirm `messageKey` extraction handles the fixed message types
   - Verify `FOOTER_ACTION` messages from footer reach background handlers

### Phase 3: Provider & Settings (P2) — FR-011 through FR-014

7. **Wire language detection** (`playback-service.ts:347`)
   - Replace hardcoded `null` with detected language from language handlers
   - Pass language to `AudioRequest` for provider-specific voice selection

8. **Fix export dependencies** (`export.handlers.ts` + `container.ts`)
   - Either call `setExportDependencies()` in `initHexagonalArchitecture()`
   - Or simplify by removing hexagonal wrapper and routing directly to legacy handler
