# Visual assets — the editorial art lane

Proso's **brand marks are deterministic vector**, produced by `specs/161-brand-vector-system`
and guarded by `scripts/verify-brand-assets.mjs`: edit the construction source, regenerate,
require byte-exact equality. Nothing generated by a model may enter `brand/`, the icon
topology, or the site identity assets.

This document covers the *other* half: **editorial art** — illustrations for the README,
release announcements, the support page, and social cards. That art is made by driving the
ChatGPT web UI on the server browser fleet (a real logged-in Chrome for the identity
`chatgpt-c`, ChatGPT Pro), the same lane Lectrice uses for its brand art. No API key, no
per-image cost; the identity, its quirks and its failure modes are documented in
`3. Resources/🛠️ Tools/GPT via the server fleet — workspace cookbook` in the vault.

## Where art goes

| Path | Contents |
|---|---|
| `packages/site/assets/images/art/<id>.png` | the generated illustration |
| `packages/site/assets/images/art/<id>.png.provenance.json` | how it was made: prompt, tool, identity, sha256 |

**Every art file carries its provenance.** `make art-provenance` (also part of `make verify`)
fails when a sidecar is missing, its sha256 no longer matches the bytes, or a required field
is empty. An image nobody can trace back to a prompt does not ship.

## Making one

```bash
# one prompt id from scripts/visuals/prompts.json
node scripts/visuals/generate-art.mjs listening-hero

# with a reference image (the anchor — see the method below)
node scripts/visuals/generate-art.mjs listening-hero --ref packages/site/assets/images/og-image.png

# the default identity is the automation account; if its composer is occupied by
# another driver the run refuses (status "refused") rather than merging two prompts
node scripts/visuals/generate-art.mjs listening-hero --identity openai-platform

# check the lane is reachable before waiting on it
~/Documents/Code/personal/web-automation/bin/web-warm chatgpt-c    # or: gpt-image --help
```

The generator shells out to `gpt-image` (the fleet shim) and writes both the image and its
sidecar. `--out` is not configurable on purpose: art belongs in the art directory, where the
provenance gate can see it. The lane only exists on hosts that have the fleet shims; the
script says so and exits `3` rather than pretending.

## The Projects route (measured 21/09/2026)

A ChatGPT **Project** holds the brand context once, so every later thread starts from it
instead of from a re-explained brief. The Proso project is set up, and `brand/chatgpt-project/`
in this repository holds its brief and attachments — project URL, the measured UI path
(steps that guessing gets wrong), and the tool that automates it are documented there.

Two things we learned by doing it, worth keeping:

- The attachments matter more than the prompt. The board came back using the *exact* hexes
  from the palette card and the mark's real proportions, because the real PNGs were in the
  thread — prose about a mark does not survive contact with the model.
- Generation inside a project works (the older note that a project "silently produced
  nothing" was about a mis-clicked sidebar entry, not about projects). The lane's refusal
  guard still applies, and firing the same prompt into a fresh chat is still the fallback.

## The method (do not improvise around it)

1. **Anchor once, then edit.** Generate one approved direction, then make every later asset
   an *edit* of it: `--ref <anchor>` with a two-column prompt — *preserve* (palette, shape
   language, line weight, negative space) and *change* (only what this asset needs).
2. **The reference must embody the intended grammar.** A chunky raster makes the model
   faithfully copy the chunk. `og-image.png` is a good anchor: it is the real lockup on the
   real navy.
3. **No rendered text, ever.** Model-drawn letterforms approximate type. The wordmark is the
   vector lockup; if an asset needs words, they are composited from `brand/svg/` or written in
   HTML beside the image — never painted by the model.
4. **Palette is fixed:** navy `#010616`, ink `#F8F8F9`, accent green `#21F299`. Anything else
   is a rejected direction, not a variation.
5. **A raster is direction, not an asset.** Pick the direction, then keep it as the anchor for
   the family of assets. Redrawing it as vector is the upgrade path, not a requirement here.
6. **Serialise heavy runs.** Text asks are cheap; image generations on one identity are queued.
   A batch fired in parallel is indistinguishable from one that silently failed.

## Anti-generic bans

The lane is judged on the same standard as the brand: if it reads as stock imagery, it is
wrong. Reject: glowing blue orbs or "AI brain" iconography, humanoid heads with circuits,
photorealistic stock people, gradient-on-gradient with no composition, speech bubbles
containing pseudo-text, and any letterform painted by the model.

## Failure modes (each one measured, from the cookbook)

| Symptom | Cause | What to do |
|---|---|---|
| `status: "refused"` | another driver left text in the shared composer — the JSON's `detail` quotes the foreign draft | retry later; never loop. Measured 21/09/2026: `chatgpt-c` held an unrelated draft from another project's driver, and refusing is the *correct* behaviour — switch identity with `--identity` instead of clearing someone else's work |
| `status: "session"`, exit 4 | the identity logged out or hit an anti-bot wall | **Pedro-gated** — do not script a relogin |
| `status: "timeout"` + a screenshot path | long generation, reasoning pause or refusal | read the screenshot, then raise `--timeout` |
| the saved image is the reference | baseline taken after upload | the driver already scopes to post-prompt assistant turns; check `baseline_images` and `candidates` |
| `fetch-failed: … are not an image` | the signed CDN URL expired into HTML | retry; bytes must be grabbed in the same run |
