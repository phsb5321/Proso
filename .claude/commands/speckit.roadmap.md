## Usage Examples

```bash
# Review a specific checklist file
/speckit.roadmap specs/024-settings-page-redesign/checklists/full-coverage.md

# Auto-discover checklists in current feature directory (prompts if multiple found)
/speckit.roadmap

# Resume a partially completed review
/speckit.roadmap  # Automatically resumes from first pending item
```

## User Input

```text
$ARGUMENTS
```

You **MUST** consider the user input before proceeding (if not empty).

## Overview

This command provides a guided workflow for reviewing requirements quality checklists generated by `/speckit.checklist`. It presents each item one at a time, allows marking items as Pass/Fail/Skip, records findings for failed items, and generates summary reports.

## Execution Steps

### Step 1: Setup and Checklist Resolution

1. Run `.specify/scripts/bash/check-prerequisites.sh --json` to get FEATURE_DIR
2. If `$ARGUMENTS` contains a path, use it as the checklist file
3. Otherwise, discover checklists in `FEATURE_DIR/checklists/` directory

### Step 2: Parse Checklist

1. Read the checklist file
2. Extract metadata (title, purpose, created date)
3. Extract categories (## headings)
4. Extract items with status, ID, text, and tags
5. Calculate statistics

### Step 3: Session Management

1. Detect if this is a new session or resume
2. Find the first pending item
3. Display welcome/resume message with stats

### Step 4: Item Review Loop

For each pending item:
1. Display item with category context
2. Prompt for action (Pass/Fail/Skip/Back/Status/Exit)
3. Process action and update file
4. Advance to next pending item

### Step 5: Summary Generation

When all items reviewed or user requests:
1. Generate summary statistics
2. List all findings by category
3. Offer save options

## Implementation

### T010-T012: Setup and Resolution

First, get the feature directory and resolve the checklist file:

```bash
# T010: Get feature directory from current branch
PREREQ_JSON=$(bash .specify/scripts/bash/check-prerequisites.sh --json 2>/dev/null)
FEATURE_DIR=$(echo "$PREREQ_JSON" | grep -o '"FEATURE_DIR":"[^"]*"' | cut -d'"' -f4)
```

**Checklist Resolution Logic (T011-T012):**

1. If `$ARGUMENTS` is a valid file path, use it directly
2. Otherwise, use Glob tool to discover files in `$FEATURE_DIR/checklists/*.md`
3. If multiple checklists found, use AskUserQuestion to let user choose
4. If no checklists found, display error and exit

### T021-T028: Item Actions (User Story 2)

**T021: Action Menu via AskUserQuestion:**

```
Question: What action for {item_id}?
Options:
- ✅ Pass - Mark as passing, advance to next
- ❌ Fail - Mark as failing, record finding
- ⏭️ Skip - Skip for now, advance to next
- ⬅️ Back - Return to previous item
- 📊 Status - View progress breakdown
- 🚪 Exit - End session with summary
```

**T022: Pass Action:**
Use Edit tool to change `- [ ] {item_id}` to `- [x] {item_id}` at the item's line number.

**T023-T024: Fail Action:**
1. Use AskUserQuestion to prompt: "Describe the finding for {item_id}:"
2. Use Edit tool to:
   - Change `- [ ] {item_id}` to `- [!] {item_id}`
   - Insert `  > Finding: {user_finding}` on the next line

**T025: Skip Action:**
Advance to next pending item without modifying the file.

**T026: Back Action:**
Return to the previous item in the list (regardless of status).

**T027: Next Item Advancement:**
After Pass/Fail/Skip, find the next pending item and present it.

**T028: Exit Action:**
Display progress summary and end the session gracefully.
